Reference pages are for exact details. Use them when you already know what you want to configure, call, run, or debug.

## What belongs here

Reference content includes provider API surfaces, provider CLI commands, environment variables, deployment settings, local development commands, generated API workflows, and ABI workflows.

## What belongs elsewhere

Task based requestor guidance belongs in [Requestors](/docs/requestors). Provider operation guidance belongs in [Providers](/docs/providers). Shared explanations belong in [Concepts](/docs/concepts).

## Source of truth

Generated APIs, ABI files, and package specific settings should be treated carefully. When generated files exist, the generation workflow is the source of truth, not manual edits to generated output.
