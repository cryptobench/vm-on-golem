Provider installation depends on whether you want the graphical desktop app, headless CLI operation, or a source checkout for development.

## Provider Desktop

Provider Desktop is the packaged graphical app for providers on machines with a visual desktop. Download the desktop installer from GitHub Releases, install it, and start the provider from the app.

The desktop app wraps provider workflows such as overview, VMs, streams, monitoring, alerts, webhooks, pricing, resources, and settings. It does not replace the provider server; it provides a focused interface for controlling and observing provider behavior.

## Headless CLI

The CLI path is intended for servers without a GUI, SSH sessions, and automation. Use `golem-provider start` as the normal production start command.

Install and start:

```bash
curl -fsSL https://raw.githubusercontent.com/cryptobench/vm-on-golem/main/install/provider-cli.sh | sh
golem-provider start
```

On Windows PowerShell:

```powershell
irm https://raw.githubusercontent.com/cryptobench/vm-on-golem/main/install/provider-cli.ps1 | iex
golem-provider start
```

To install and start in one step:

```bash
curl -fsSL https://raw.githubusercontent.com/cryptobench/vm-on-golem/main/install/provider-cli.sh | sh -s -- --start
```

On Windows PowerShell:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/cryptobench/vm-on-golem/main/install/provider-cli.ps1))) -Start
```

The installer downloads the standalone CLI binary from GitHub Releases, verifies the release checksum, installs or verifies Multipass, and validates provider host requirements.

Provider networking heads-up: public providers need inbound ports `80`, `443`, and `50800-50900` forwarded from the router/firewall to the provider machine. `golem-provider start` checks this during startup.

## Source install

Source install is for contributors or operators who need repository level control. It uses the provider server package directly and is useful when developing features, running tests, or debugging service behavior.

Use source install only when you need that control. Normal providers should prefer the packaged path once available for their environment.

Install from a checkout:

```bash
cd provider-server
poetry install

poetry run golem-provider --help
```

Run source commands through Poetry:

```bash
poetry run golem-provider start
poetry run golem-provider status
```

## Install validation

After installation, `golem-provider start` performs the required startup checks. Use `golem-provider status`, `golem-provider summary`, and `golem-provider watch` for optional inspection while the provider is running.
